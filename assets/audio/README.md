# Hausa audio library

`ha/` holds one recording per spoken line, named by clip id. `manifest.json`
lists every line the app can say and is the input to the generator.

```bash
npm run audio:manifest    # rebuild manifest.json from the app's Hausa strings
# ...generate on a GPU machine (see ../../tools/generate_audio.py)...
npm run audio:registry    # rebuild constants/audioClips.ts from ha/
npm test                  # check the app and the pipeline still key lines the same way
```

Clip ids are `sha1(normalised text)`. Editing a lesson changes its id, so the
old recording becomes **orphaned** — `audio:manifest` reports these. An
orphaned clip is a recording of text that no longer exists; delete it or
regenerate.

## Why these are committed

They are the product, not a build artifact: without them the app narrates
Hausa with an English voice. The whole library is a few megabytes of AAC.

## Licence — read before a production run

The generator uses **YarnGPT-local**, published under **CC BY-NC-SA 4.0**.
Non-commercial, share-alike. Whether audio generated by an NC-SA model
inherits that licence is genuinely unsettled. Someone with authority has to
decide this before these clips ship — see the header of
`tools/generate_audio.py`.

If the answer is no, point the same pipeline at recordings made by a human
Hausa speaker. Nothing downstream cares how the WAV files were produced.

## Nothing here reaches a child unreviewed

The model does not model tone. Hausa is tonal. Run
`python tools/generate_audio.py --review` to produce a checklist and have a
Hausa speaker listen to every clip.
